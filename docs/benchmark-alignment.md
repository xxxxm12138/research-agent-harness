# 与金融大模型评测 / 后训练的对应

这套 harness 是为一个具体场景（一级市场投研）写的，但它要解决的问题和"定义并评测模型的金融能力、为后训练造数据"是同一类：**什么算做对、在什么信息条件下做、怎么判分、错了怎么变成下一轮的数据。**

## 一句话框架

能力 = 在给定信息集下，把模糊的真实需求变成可核查的专业产出。评测要同时控制三样东西：**题目（query）**、**信息环境（workspace）**、**判分（reward）**。

## 对应关系

| 环节 | 本仓库 | 评测 / 后训练中的对应 | 说明 |
|---|---|---|---|
| 能力定义 | `agent/router.md` 的路由与意图（mapping 底稿 / 人物背调 / 赛道研判 / CR / 建模 / 筛选 / 叙事） | 任务分类体系 | 每个路由 = 一类能力；`Not` 列定义易混淆的相邻能力 |
| 题目 | `agent/evals/cases/*.md`：真实交互里杂乱的原始输入 | 真实场景 query | 题目保留截图、语音、半句话这种噪声，而不是清洗过的标准问法 |
| query 改写 | Intent Gate + Task Packet | 意图识别、query rewriting | 把"看看这个赛道"改写成核心问题、读者决策、证据标准、翻转条件 |
| 拒绝猜测 | `RoutingError` → 先问一个问题 | 歧义识别、澄清能力 | `cases/ambiguous_intent.md` 专门测这一点 |
| 信息环境 | `workspace.assemble` + `materialize` | 评测时的上下文构造 | 只给该任务需要的材料；缺什么显式列出 |
| 防泄露 | `asof` 时点冻结 + `TemporalGate` | 时间切分、防止 look-ahead | 决策日之后的材料不进工作区 |
| 噪声与缺口 | 来源分级（BP、截图、访谈 vs 公告、报道） | 干扰项、信息缺口设计 | 好的题目故意放入单方数据与传闻，看模型会不会当事实用 |
| 过程监督 | 8 个关口，各自对应一个检查点 | process reward / 过程可验证项 | 每个关口都是可以程序判定的二值信号 |
| 结果评分 | rubric：6 维规则分 + 判断质量交给 judge | outcome reward：可验证项 + LLM-as-judge | judge 未给分时结论为 `provisional`，不把不确定当确定 |
| 示范数据 | `agent/golden/` 与通过全部关口的 run | SFT 示范 | 过关口 + 高分的产出才进 golden |
| 偏好数据 | 同一任务的合格 / 不合格 run（如 `run.json` vs `run_bad.json`） | 偏好对（chosen / rejected） | 关口错误信息可直接作为 critique |
| 错误分类 | `agent/memory/failure_patterns.md` | 错误分析、定向造数 | 每类失误标明由哪个关口捕获 |
| 数据飞轮 | 纠错记录 → 规则 → 关口；每周升级 golden 与用例 | 迭代式数据构造 | 用户纠正是最便宜的高质量标注 |
| 模型对比 | `irh run --model` | 同一 harness 下的模型横评 | 固定题目、工作区与判分，只换模型 |
| 个性化 | `style-replication` + `thinking-style-recognition` + `user_judgment.md` | 千人千面的输出 | 换掉这三份文件即换一位读者；评测个性化时它们是控制变量 |

## 能力边界：这套方法能测什么、测不了什么

- **能测的**：意图理解是否到位、信息纪律（来源、时点、状态标签）、结构是否符合专业规范、过程是否按检查点推进、是否把单方数据当事实。这些都能写成规则，判分稳定、便宜、可复现。
- **只能半测的**：分类轴选得好不好、画像是否抓住关键差异。rubric 只能检查"有没有主轴、主轴是否先于玩家"，好坏仍需要专家或 judge。
- **测不了的**：投资判断本身对不对。一级市场的结论要很久以后才能验证，且高度依赖未公开信息；评测应当衡量"判断的依据是否充分、翻转条件是否可观测"，而不是结论的对错。
- **一个常被忽略的泄露**：时点冻结只约束交给模型的材料，不约束模型预训练里已有的知识。做时点类评测时，要么选模型知识截止日之后的事件，要么把实体匿名化（本仓库示例全部虚构，正是这个思路）。

## 从这里出发造一个评测集

1. 从真实交互里收集杂乱输入，按路由分类（能力维度），每类覆盖"清楚 / 歧义 / 含干扰信息"三种难度。
2. 为每道题构造时点工作区：一组有日期、有 origin 的来源，故意放入 BP 自报、截图传闻和决策日之后的材料。
3. 写机器可判的期望：路由、必须排除的相邻意图、必须入池的项目、不得超过的标签上限。
4. 规则维度用关口与 rubric 自动判；判断维度用 LLM-as-judge，并抽样人工复核 judge。
5. 失败样本连同关口错误信息，作为 critique 或偏好对进入后训练数据。
