# 研究员工作风格画像

本文件描述 agent 服务的研究员（下文称 reviewer）。换一位 reviewer 时，替换本文件与 `agent/memory/user_judgment.md`，其余结构不变。本文件是怎样从工作痕迹里提炼出来的，见 `skills/style-replication/DEVELOP.md`。

---

## 1. 身份

- 一级市场 FA 机构 AI 组的投研实习研究员，支持 senior 的投资与融资判断。
- 分工：信息处理交给 AI，思维脚手架由 AI 辅助，判断由人做。

## 2. 工作范围

| 类型 | 占比（约） | 典型任务 |
|---|---|---|
| 赛道研究 | 40% | 赛道 mapping、竞争格局、赛道研判 |
| 项目投研 | 20% | 项目画像、cap table、投资备忘录素材 |
| AI 能力建设 | 20% | Skill 设计、agent 架构、方法论迭代 |
| 其他 | 20% | 学术尽调、Call Report、对外材料 |

## 3. 思维方式（信条 → 习惯 → 模式）

**信条**

- 分析是判断的载体，不是信息的容器。
- 一级市场判断高度主观：Skill 是脚手架，不是打分器。
- 判断不外包给 AI：做不出好判断的环节宁可不自动化（例如不做"自动写 IC memo"的 agent）。

**习惯**

- **反复收紧边界**：先放宽，再质疑分类、去掉重叠，最后锁定一个可用的轴。
- **先底表后结论**：项目池、表格字段、排序规则、信息状态先于漂亮的段落。
- **用样例做测试**："先写 2 个我看看"意味着先给校准样本，而不是整章。
- **图是分析界面**：每个颜色、数字、筛选和遗漏都要有理由。
- **口径比格式重要**：分类不严谨的漂亮报告是错的。
- **纠正是训练数据**：重复的纠正要变成规则，而不是一次性修改。

**模式**

- 具体性阶梯：数字 > 案例 > 类比 > 直觉；时间写具体节点。
- 每个"是"配一个"不是"。
- 不确定性条件化："若 X 则 Y"，而不是"仍面临挑战"。

## 4. 质量标准

交付前自检：

```
□ 结论明确，或明确说明为什么此处不下结论（mapping 底稿）
□ 每个关键数字有来源、日期与信息状态
□ 估值 / 融资有具体数字，或标注「未公开 / 待DD」
□ 不确定性条件化
□ 写出竞争动态，而非静态卡片
□ 有 inflection / 验证节点
□ 事实层与分析层分开
□ 有给 reviewer 的汇报层
```

**拒收表（零容忍）**

| 拒收 | 例子 |
|---|---|
| 格式漂移 | 表格列错位、同一日期多行、模板章节缺失 |
| 事实错误 | 日期、金额、名称与来源不符 |
| 重复或敷衍 | 不同条目内容雷同、用空话填格子 |
| 未验证就交付 | 没跑自检、计数没重算、链接没打开 |

## 5. 沟通偏好

- 简洁，不用寒暄式开场。
- 中文为主，公司名与技术专有名词保留英文。
- 出错直说，不编造。
- 非平凡任务先确认模板再执行。
- 写给两个读者：正式产出 + 通俗汇报。
- **少问也懂我**：只问 1–3 个影响结果的问题；拿不准时，优先给一个小的可检查物，而不是一篇长稿。
- 纠正词是停止信号：`不是` / `你需要先` / `不要` / `先和我确认` / `理解错了` / `这个太散`。

## 7. 项目结构

- 按赛道 / 项目分目录，目录内分 `reference/`（原始材料）和 `report/`（产出）。
- 方法论在 `skills/` 下，一个 Skill 一个文件夹；每个 Skill 有铁律与常见失误表。
- 产物文件名带 `-MMDD` 日期后缀，或用 `v1`–`v4` 迭代。
- 未指定输出路径时，按这个结构推断；推断不了再问。
