# 工作风格画像 Skill：开发记录

> 复盘用：记录这个 Skill 从需求到产出的过程。它也是一份方法说明：怎样从一个人的工作痕迹里提炼出可加载的"用户模型"。

---

## 需求

从一个研究员做过的事、写过的 Skill 和对话记录里，总结其身份、角色、任务、思维方式和目标，提炼成一个 Skill，每次执行时作为背景导入：让 agent 知道能调用哪些 Skill、有哪些要求，并自己判断什么叫好。

关键要求：

- 所有 agent 通用；
- agent 加载后能自主判断输出质量，不需要每次人工纠正；
- 记录开发过程，供复盘。

---

## 信息来源与提炼方法

### 1. 已有 Skills → 设计理念

| Skill | 提取的关键理念 |
|---|---|
| 赛道分析方法论 | "分析是判断的载体不是信息的容器"；三层递进（边界 → 结构 → 动态）；断言-证据-推论-含义四步；inflection 事件表 |
| 交易建模 | "先读法律文件后动手算"；Input 与 Formula 严格区分；四步流程（条款拆解 → 法律映射 → 建模 → 验证） |
| 项目筛选 | "checklist 不是评分卡"；五个必问；三选一 + 下一步动作；"答不上来本身就是信号" |
| Call Report | 事实 / 判断 / 无效信息三层过滤；"判断归人，AI 不打分"；术语校验 |

共性模式：

- 每个 Skill 都有"铁律"（违反 = 失败）；
- 都有"常见失误"对照表；
- 都是 checklist / 脚手架定位，不替人做判断；
- 都强调具体性（数字 > 案例 > 类比 > 直觉）。

### 2. 个人规划文档 → 分层认知

- 三层架构：信息处理（AI 做）/ 思维脚手架（AI 辅助）/ 判断（人做）。
- "一级市场判断高度主观，AI 无法替代人的投资嗅觉。"
- 砍掉的东西同样重要：自动写 IC memo 的 agent 被砍掉，因为 AI 写出的判断没有信息量。

### 3. 工作日志 → 任务范围

按两个月的工作记录归类任务类型分布：赛道研究约 40%，项目投研约 20%，AI 能力建设约 20%，其他约 20%（学术尽调、建联等）。

### 4. 对话中的反馈 → 质量底线

反复出现的纠正集中在四类：格式不一致（如表格一天多行、列错位）、事实不准（如把已停止的任务写成进行中）、内容重复或敷衍、未经验证就交付。结论：对格式精确性、事实准确性、内容不重复零容忍。这四类直接成为拒收表。

### 5. 文件夹结构 → 组织方式

- 按赛道 / 项目分目录，目录内 `reference/` + `report/`；
- 方法论集中存放，每个 Skill 一个文件夹；
- 产物以日期命名，或以版本（v1–v4）迭代。

## 设计决策

### 结构参考

| 参考 | 模式 | 采用情况 |
|---|---|---|
| Claude Skills 官方文档 | frontmatter + markdown 正文 | 采用基本格式 |
| 开源个人 AI skills 合集 | 按 category 拆成 skills / agents / rules | 部分采用：只做一个综合文件 |
| 开源角色型 skills | Role definition + Core behaviors + Constraints | 采用结构模式 |
| "onboarding 访谈 → about_me.md" 的做法 | 先访谈再写画像 | 受启发，但改为直接从工作数据中提取，不做访谈 |

最终：单文件 `SKILL.md`，七节：身份 / 工作范围 / 思维方式 / 质量标准 / 沟通偏好 / 可调用 Skills / 项目结构。

### 关键选择

| 决策 | 选择 | 理由 |
|---|---|---|
| user-invocable | false | 这是背景知识，不需要用户手动调用 |
| disable-model-invocation | false | agent 应自动加载 |
| 质量标准写法 | 自检清单 + 拒收表 | 让 agent 能自主判断，不需要人每次提醒 |
| Skill 列表 | 表格 + 触发词 | agent 能快速把任务匹配到工具 |
| 思维方式 | 信条 + 习惯 + 模式三层 | 从原则到行为再到操作，逐层具体 |

## 与评测的关系

这个 Skill 本质上是一个显式的用户模型。它和 `agent/memory/user_judgment.md`、`skills/thinking-style-recognition/SKILL.md` 一起，回答"同一个问题，对这位读者，好答案长什么样"。换掉这三份文件，同一套 harness 就服务另一位读者；这也是做个性化输出评测时需要控制的变量。
