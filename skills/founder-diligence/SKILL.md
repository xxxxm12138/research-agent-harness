# 创始人 / 团队背调

**用途**：回答"这个人 / 这个团队为什么可信、缺什么、访谈该问什么"。
**核心原则**：背调是职业尽调，不是挖隐私。只用与投资判断相关的职业信息和公开信息；事实层写可核实的经历与成果，分析层写判断和推理依据。

---

## 边界（先读）

| 可以收集 | 不收集 |
|---|---|
| 教育与职业经历、任职机构与岗位 | 住址、家庭成员、联系方式 |
| 论文、专利、开源项目、产品、公开演讲 | 私人社交账号、非职业生活 |
| 公开的融资、任职、工商信息 | 聊天记录原文、群聊截图里的个人信息 |
| 公开表态（采访、博客、官方账号） | 对人格的打分或标签 |
| 招聘信息、团队公开规模 | 年龄、婚育等与能力无关的属性 |

- 截图或群聊里出现的人物信息，只提取与职业相关的事实，标 `市场线索待核验`；不复制联系方式和对话原文。
- 竞业、诉讼等法律事项只记录公开可查的信息并标 `待DD`，结论交给法务。
- 个人主页只引用职业或学术主页。

---

## 输出与组合

- 产出：`{人名}人物画像-{MMDD}.md` + 访谈问题清单。
- 只做人物：本 Skill + research-mapping Step 1（坐标系对齐）。
- 单项目深调：research-mapping Step 4–5 + 本 Skill。
- 混合任务：背调是 P0，先于 mapping。
- 创业者迁移 mapping：本 Skill 提供人物事实链，流程按 `agent/checkpoint_workflow.md` 的五个检查点。

---

## 铁律（违反任一条 = 任务失败）

1. **事实层 / 分析层分节**：数字与经历放事实层；"可信""偏弱"之类判断放分析层，并写推理依据。
2. **每条背景、融资信息带信息状态**：核实 / 公开报道 / 媒体口径 / 市场线索待核验 / 待DD / 未公开。
3. **大合著不等于主导**：大合著论文标注「贡献权重待访谈确认」。
4. **链接必填**：官网 / GitHub / Hugging Face / 学术或职业主页；没有则写「无」并给替代链接。
5. **不写成功预测，不写夸奖**：迁移 mapping 保持中性事实语气。

## 执行流程

### Step 1：Thinker 预处理

按 `skills/thinker/SKILL.md` 的 ADAS：先整理论文与公开信息（只要事实），再写初始识人判断，最后设计访谈问题。

### Step 2：事实层

无融资主体（学术 Pipeline）用人物模板：

```markdown
## [姓名] / [机构]

### 个人经历
### 研究方向与技术流派（对齐坐标轴）
### 代表性成果（按重要性，含 arXiv 编号 / 日期 / 作者位次）
### 创业信号（如有：招聘、专利、公开表态）
### Pipeline 判断
- 跟踪理由 / 预计时间窗口 / 若创业可能落点
```

有融资主体时，创始人块写进项目画像（`skills/research-mapping/reference/project-profile-template.md`）：

- 机构 / 学历 / 工业界 / 导师 / 代表性产出
- 团队密度信号：核心成员来源、合作年限、连续产出
- [可选] 一段「为什么可信」的 blockquote（属于分析层）

单行格式（用于 CR 与总表）：`职位 + 姓名：学历，关键经验，代表成果（带数字）`。不写审稿经历、毕业年份、导师 h-index。

### Step 3：团队匹配（分析层）

- 这个问题最需要什么能力？团队在这项能力上强不强？
- 已知缺口在哪？他们知道吗？有补齐计划吗？
- 核心成员以前一起做过事吗，还是新拼的？
- 大厂背景：具体主导了什么，而不是"在哪儿待过"。
- 连续创业者：上一家做到多大、用了多久、是否退出。

### Step 4：访谈问题

- 每个问题对应一个事实层缺口或一个分析层假设。
- 优先问可验证的内容：数字、时间、角色、谁做的决定。

## 创业者迁移 mapping（人物部分）

按五个检查点执行：

1. **任务理解**：对象与范围、时间与地域、是否允许使用传闻、语气、交付格式。
2. **样本池表**：人物 / 项目 · 当前领域 · 过往公司 / 岗位 · 融资 / 估值 · 信息状态 · 纳入理由。
3. **标签定义**：覆盖什么、典型公司 / 岗位、可迁移的能力、和相邻标签的区别。
4. **2–3 段样例画像**，确认语气与颗粒度。
5. **正文与可视化**。

人物事实链：`创业前经历 → 当前项目 → 最新进展 → 信息状态 / 待核验点`。传闻只有在 reviewer 允许时使用，且必须标 `媒体口径` 或 `市场线索待核验`。

报告顺序：汇总计数 → 筛选逻辑 → 总表 → 人物画像 → DD 附录。HTML 先写 insight 再放图，hover 展示样本（姓名、项目、融资 / 估值、信息状态）。常用图：能力 × 方向矩阵、背景迁移图。

## 常见失误

| 失误 | 修正 |
|---|---|
| 把履历写成流水账 | 只保留与当前项目相关的经历和代表成果 |
| 合著论文当个人成果 | 标注作者位次与「贡献权重待访谈确认」 |
| 判断混进事实层 | 「技术审美好」之类挪到分析层并写依据 |
| 用截图信息当事实 | 标 `市场线索待核验`，进入 DD 清单 |
| 收集与能力无关的个人信息 | 删除；回看边界表 |
| 迁移 mapping 写成趋势论证 | 回到检查点 1，按事实链写 |

## 自检清单

```
□ 没有收集边界表右栏的任何信息
□ 事实层与分析层分节
□ 每条背景 / 融资信息带状态
□ 大合著论文已标注贡献权重待确认
□ 链接齐全，或写明替代链接
□ 访谈问题与缺口一一对应
□ 迁移 mapping：样本池与标签定义先于画像；语气中性；计数来自最终表
```
