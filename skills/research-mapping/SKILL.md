# 投研 Mapping

**用途**：把一个赛道或一个待见项目整理成可供判断的"地图"：边界、坐标轴、项目池、总表、机构与项目画像、来源附录。
**核心原则**：Mapping 是地图，不是名单。先定边界和坐标轴，再把玩家放进去；事实带信息状态，判断留给读者，或在任务要求时明确给出。

配套材料：

- `skills/research-mapping/reference/project-profile-template.md`：五段式项目画像 / 人物画像模板
- `skills/research-mapping/reference/bigtech-boundary-template.md`：大厂格局边界章节写法
- 论证与语言规范：`skills/track-analysis/SKILL.md`
- 人物背调：`skills/founder-diligence/SKILL.md`
- 图表：`skills/landscape-visualization/SKILL.md`
- 结构示范（虚构数据）：`examples/ai-companion-hardware/report.md`

## 铁律（违反任一条 = 任务失败）

1. **Intent Gate 先行**：动笔前判断任务是 mapping 底稿、人物迁移 mapping、memo、pitch 还是 CR，并写明"它不是什么"。mapping 底稿不给 FA 匹配，也不给"应该找谁 / 应该投谁"。
2. **先确认再展开**：Task Packet、分类轴、项目池、样表、机构写法、来源策略先给 reviewer 确认；只问 1–3 个真正影响结果的问题。
3. **坐标系先于玩家**：边界（是 / 不是）→ 能改变结论的轴 → 放玩家。
4. **一个主分类轴**：不把技术路线、产品形态、用户场景、融资阶段、硬件形态混在一套分类里；边缘案例单独说明归属理由。
5. **项目池先于画像**：凡已融资或被 reviewer 点名的项目，先进项目池（附纳入理由、信息状态、拟归类），确认后再写画像。
6. **信息状态必标**：每个融资、估值、投资方、背景信息都带状态标签，且不得强于来源允许的上限。
7. **计数从最终总表重算**：Summary 里的数量和占比从最终总表计算，不抄旧稿。

## 执行流程

### Step 0：解析输入，写 Task Packet

- 从截图、群聊、语音、链接中提取：任务类型、优先级、截止时间、决策时点（`asof`）、实体、产出格式、参考材料。
- 跑 Intent Gate，按 `agent/task_packet_template.md` 写 Task Packet。
- 给 reviewer 一个最小可检查物：分类轴草案 + 项目池草案 + 总表字段 + 来源策略。此时不写长文。

### Step 1：海外参照系 + 估值锚（或坐标系对齐）

- 海外参照只用来对齐坐标系、提供估值锚，不和国内项目放在一张表里直接比较。
- 每个参照写：做什么（一句话）→ 处在哪个坐标 → 最近一次融资 / 估值（带状态与日期）→ 对国内项目意味着什么。
- 人物背调场景只做本步，用来确定这个人所在的技术坐标。

### Step 2：国内玩家 Mapping（分类轴 + 项目池 + 总表）

1. **定边界**：这个赛道是什么、不是什么；和相邻赛道切在哪里。
2. **选主轴**：候选轴逐个做"两家公司测试"：拿两家公司问"它们最重要的差异是什么"，轴抓不住这个差异就换轴。
3. **建项目池**：已融资项目、被点名项目、公开报道出现的项目全部入池；每条带纳入理由、信息状态、拟归类。
4. **写分类定义**：每一类写清覆盖什么、典型项目 / 形态、核心能力、和相邻类别的区别；边缘案例写归属理由。
5. **出总表**：按类别分组，类内按已披露融资金额排序；金额未披露的排在类末并标 `未公开`。

### Step 3：趋势 + 大厂边界

- 趋势写动态，不写现状清单：谁在打时间差、技术差、资源差；A 赢了 B 会怎样。
- 大厂章节按 `skills/research-mapping/reference/bigtech-boundary-template.md`：三段式 + 组织背景；cap table 竞品、商业化替代、客户 / 战投三种关系分开写，单独标出人才外流信号。

### Step 4：画像

**机构画像**（deal-led，只写四项）：

| 字段 | 写什么 |
|---|---|
| 机构属性 | 美元 / 人民币、财务 / 产业 / 国资、基金规模（有公开数据时） |
| 投资项目 - 金额 | 本赛道相关的投资项目、轮次、金额（带状态） |
| 投资过程 | 领投 / 跟投、轮次间隔、是否连续加注 |
| 可观察偏好 | 从投资行为能看出的偏好，用「可观察到 / 可能说明 / 待DD」表述，不写成推荐 |

排序：按基金规模、机构重要性，或 reviewer 认可的其他口径。

**项目画像**：五段式，见 `skills/research-mapping/reference/project-profile-template.md`：背景 → 估值 & 融资 → 赛道（坐标轴、核心命题、对标）→ 技术路径（里程碑与数字）→ 分类判断。mapping 底稿里的"分类判断"只写归类理由与待验证点；Engage / Watch / Pass 建议只在任务要求时给出。

**Lab 模式**：文档最前面放 9 列 Summary 表，每格带信息状态（✓核实 / 待DD / 待BD / 媒体口径），技术路线用一句话 + 与主流架构的差异。

| 赛道 | 公司 | 成立 | 估值 | 融资 | 具体领域 | 创始人 | 团队背景 | 官网 |
|---|---|---|---|---|---|---|---|---|

### Step 5：BP 共创 / storyline

- 只在 Pitch 场景且 reviewer 要求时进入本步。
- 叙事结构用 `skills/narrative/SKILL.md`：世界变化 → 赢家与输家 → Promised Land → 功能即道具 → 证据。
- 每个卖点挂一个可核实的 proof point；没有 proof 的卖点标 `待DD`，不进入对外材料。

### Step 6：自检 + 汇报

- 跑文末自检清单与 `agent/playbook.md` 的 Output Self-Check。
- 从最终总表重算 Summary 计数。
- 写给 reviewer 的通俗汇报：任务背景、行业 know-how、做了什么、关键发现、可进化点。
- 附 run record（`agent/run_record_contract.md`），交给 `irh check` 与 `irh score`。

## 报告结构（mapping 底稿默认）

```
1. Summary（样本口径 + 3-5 条可观察发现；计数来自最终总表）
2. 分类口径与边界（主轴、各类定义、边缘案例）
3. 项目池与 Mapping 总表（按类别分组，类内按已披露金额排序）
4. 机构画像（deal-led 四项）
5. 项目画像（五段式，按类别）
6. 信息来源与核验状态（附录：来源编号、日期、origin、状态、待核验点）
```

除非 reviewer 明确要 memo、论点或单公司结论，否则不改这个顺序。跨案例的判断性问题放在汇报层，不进正式报告。

---

## 信息状态标签

| 标签 | 何时用 |
|---|---|
| `核实` | 工商、公告、监管披露，或多源交叉核验 |
| `公开报道` | 正式媒体报道、公司官方发布、论文 |
| `媒体口径` | 自媒体、二手转述 |
| `市场线索待核验` | 截图、群聊、传闻（含 `用户截图线索，待DD`） |
| `待DD` | BP、创始人口述、访谈口径 |
| `推演` | 基于事实的推断，必须写出推理依据 |
| `未公开` | 明确未披露（如金额未公开） |

口径打架时写「待对齐」，并在附录列出各来源的说法；不为顺滑而取平均或只挑一个。

## 常见失误

| 失误 | 症状 | 修正 |
|---|---|---|
| 名单冒充 Mapping | 一上来就是公司列表 | 先写边界和主轴 |
| 多轴混分 | 技术路线、硬件形态、场景并列成一级分类 | 选一个主轴，其余维度放进总表字段 |
| 池子不全就写画像 | reviewer 问「为什么没有 X」 | 回到 Step 2 补池，再写画像 |
| 机构画像写成基金百科 | 成立年份、管理规模、明星项目大段介绍 | 只写四项，围绕本赛道的投资行为 |
| 状态标高 | BP 数字写成「核实」 | 按来源上限降级，附录说明 |
| 判断越界 | mapping 底稿结尾写「建议找某机构」 | 删除；确有必要时放到汇报层，作为留给 reviewer 的问题 |
| 计数过期 | Summary 和总表对不上 | 从最终总表重算 |
| 后视泄露 | 用了决策时点之后才发布的融资消息 | 按 `asof` 剔除，附录注明"时点后信息未使用" |

## 自检清单

```
□ Intent Gate 已写，明确了"不是什么"
□ 边界清楚：每个"是"有对应的"不是"
□ 只有一个主分类轴，边缘案例有归属理由
□ 已融资 / 被点名项目全部在项目池，且有纳入理由
□ 总表按类别分组、类内按已披露金额排序
□ 机构画像只有四项，且围绕本赛道投资行为
□ 每条融资 / 估值 / 投资方信息带状态标签，没有超过来源上限
□ 没有使用 asof 之后发布的材料
□ Summary 计数从最终总表重算
□ mapping 底稿没有未被要求的投资建议
□ 附录列出来源编号、日期、状态与待核验点
□ 已写汇报，并附 run record
```
