# 单项目 / 人物画像模板

五段式画像，适用于 Pitch 前 deep dive 与 BP 共创前的项目理解。

---

## 项目画像（有融资主体）

```markdown
## [序号]. [公司名] / [创始人]

### 个人经历 / 组织背景
- 创始人履历：机构、学历、工业界经历、导师、代表性产出
- 团队密度信号：核心成员来源、合作年限、连续产出
- [可选 blockquote] 一段「为什么这个人 / 团队可信」的叙述性总结（属于分析层）

### 估值 & 融资
- 轮次、金额、估值（标注状态：✓核实 / 公开报道 / 媒体口径 / 待DD / 未公开）
- 投资方（如有）
- 低调或高调的融资策略本身是否是信号

### 赛道
- **所属坐标轴**：[本次 Mapping 的主轴上的位置]
- **核心命题**：一句话技术或商业赌注（解决什么根本约束）
- **与海外 / 大厂对标**：[能力上限锚 / 直接竞品 / 无对标]
- [可选] 对比表：与 1–2 个同轴玩家的差异

### 技术路径
- **已验证里程碑**：[开源模型 / benchmark / demo 指标 / 出货量]
- **在研方向**：[未公开，但可从招聘 / 论文推断，标 `推演`]
- **产品矩阵**（如有）：基座 → 上层应用逻辑
- 关键数字：参数规模、成功率、TPS、续航、BOM 等可量化指标

### 分类判断
- **归类理由**：为什么落在这一类，边缘情况如何处理
- **四维评分**（任务要求时）：团队密度 X + 技术原创性 X + Research-first X + 独立性 X = 总分
- **档位**（任务要求时）：[强 / 准 / 应用创业 / Pipeline / 待核实]
- **bull case**（一句）
- **bear case**（一句）
- **建议**（仅在任务要求时）：[Engage / Watch / Pass] + 下一步验证动作
```

## 人物画像（无融资主体 / 学术 Pipeline）

叠加 `skills/founder-diligence/SKILL.md`，结构简化为：

```markdown
## [姓名] / [机构]

### 个人经历
### 研究方向与技术流派（对齐坐标轴）
### 代表性成果（按重要性，含 arXiv 编号 / 日期 / 作者位次）
### 创业信号（如有：招聘、专利、公开表态）
### Pipeline 判断
- 跟踪理由 / 预计时间窗口 / 若创业可能落点
```

事实层与分析层分节；大合著论文标注「贡献权重待访谈确认」。

## 大厂段落（格局边界）

不用五段式，改用三段式，详见 `skills/research-mapping/reference/bigtech-boundary-template.md`：

```markdown
### [序号]. [公司 / 部门]

- **组织背景**：体内位置、是否独立融资
- **在做什么**：[技术线 + 代表项目 / 论文 / 产品]
- **做得如何**：[国内 / 全球梯队判断 + 公开痛点]
- **对创业的意义**：
  - cap table 竞品？（通常否）
  - 商业化替代风险？
  - 客户 / 战投角色？
  - 人才外流信号？
```

---

## 写作要点

1. **叙述与结构并存**：关键判断用 blockquote 写一段连贯论述，事实用 bullet。
2. **数字优先**：「4090 上 500+ TPS」优于「推理效率高」。
3. **边界清晰**：每个「是」对应一个「不是」。
4. **不混层**：融资数字放事实层；「估值偏高」放分析层并给推算逻辑。
5. **链接必填**：官网 / GitHub / Hugging Face / 学术或职业主页；没有则写「无」并给替代链接。

---

## 质量自检（单条画像）

```
□ 坐标轴标签明确
□ 核心命题一句话可复述
□ 至少 1 个可核实的技术或商业 proof point
□ bull / bear 各一句，且不空泛
□ 分类举例逻辑正确（不用相邻类别的案例反证本类）
□ 融资信息标注状态
```
