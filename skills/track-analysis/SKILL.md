# 赛道分析方法论

**用途**：本文档是赛道分析的写作规范，供 AI 工具（辅助生成赛道分析报告）和分析师（手动撰写）共同使用
**文档结构**：本文件是规则总纲；`skills/track-analysis/reference/track-brief.md` 是赛道研判的六节骨架与技术深度标准（控制方程 → 必然流水线 → 每阶段挂投资判断）

**适用场景**：新兴技术赛道的初始Mapping、项目跟踪分析、投资备忘录撰写
**核心原则**：分析是判断的载体，不是信息的容器

---

## 使用方式

当用户说 `/赛道分析` 或"帮我分析这个赛道"时，**先确认这三个问题**（不回答不动笔）：

> 1. **这篇分析要回答什么问题？**（一句话，不是"分析XX赛道"这种废话）
> 2. **读者读完后应该做什么不同的决定？**
> 3. **什么证据会让你改变结论？**（没有答案 = 你写的是信仰而非分析）

用户的答案是分析的骨架。先定骨架，再填内容。

## 常见失误（输出前检查）

| 失误 | 症状 | 修正 |
|------|------|------|
| 信息整理伪装成分析 | "A做了X，B做了Y，C做了Z，所以赛道竞争激烈" | 每条信息都问"所以呢？对投资判断意味着什么" |
| 框架先行 | 先套波特五力/SWOT，再往里塞内容 | 框架是最后的整理工具，先问问题 |
| 论点论据分离 | 摘要说"数据壁垒是护城河"，证据散落第4/6/8章 | 每个核心论点的证据紧跟其后 |
| 分类框架多而乱 | 6条技术路线、3种商业模式、5种数据类型全部并行 | 选一个主分类轴，其他维度作为补充 |
| 结论模糊 | "仍处早期"、"值得关注" | 说清楚不确定的是什么，达到什么条件才会确定 |
| 缺少竞争动态 | 每个玩家单独描述，像人物档案卡片 | 明确问：如果A成功，B会怎样？ |

## Mapping 的结构逻辑

### 正确顺序

```
先建坐标系（地图）
    ↓
再把玩家放进去
```

坐标轴通常是：
- 横轴：技术路线（做什么）或价值链位置
- 纵轴：商业化进度 或 壁垒强度

**关键**：坐标轴要能区分玩家的战略差异，不能用来区分的轴就不是好轴。

### 三层递进

```
第一层：赛道边界（这是什么，不是什么）     ← 现状描述
    ↓
第二层：竞争结构（谁在哪个位置，为什么）   ← 开始分析
    ↓
第三层：动态变化（格局会怎样演化）         ← 真正的分析
```

### 好分类维度的三个标准

- **互斥性**：放入某一类的玩家不可能同时在另一类
- **完备性**：所有主要玩家都能被放进去
- **可操作性**：分类结果直接影响投资判断

**测试方法**：拿两家公司，用分类轴问"它们最重要的差异是什么"——如果轴捕捉不到这个差异，轴选错了。

## 深度分析的论点-论据结构

### 分析的基本单元

```
【断言】一句话判断，有立场，可被证伪
    ↓
【证据】支撑断言的具体事实（数字 > 案例 > 类比 > 直觉）
    ↓
【推论】证据和断言之间的逻辑连接（这步最常被省略）
    ↓
【含义】对投资决策的影响（所以应该做什么/不做什么）
```

**示例对比：**

❌ 差版本：
> "数据是世界模型赛道最真实的护城河。宇树卖了很多机器人，Wayve有2000万小时数据。"

✅ 好版本：
> "数据护城河的强弱取决于是否有自动扩张的闭环，而非数据量本身。[断言] 宇树每卖一台机器人就多一个采集节点，成本边际递减；Wayve的数据则依赖持续的路测运营，成本线性增长。[证据] 同样的'数据量优势'，前者随时间拉大差距，后者只是当前快照。[推论] 因此评估数据壁垒时，问的不是'现在有多少数据'，而是'12个月后这个差距会变大还是缩小'。[含义]"

### 论据质量层级

```
1. 可量化的一手数据（收入、客户数、留存率）      ← 最强
2. 可验证的第三方事件（融资、产品发布、合同）
3. 有据可查的技术指标（论文数据、benchmark）
4. 行业观察者的公开判断（analyst报告）
5. 逻辑推演（类比、理论推断）
6. 直觉/感受                                    ← 最弱
```

当最强证据是层3或以下时，结论要相应保守。

### 不确定性处理

| 类型 | 定义 | 正确处理 |
|------|------|---------|
| 已知的未知 | 知道自己不知道什么 | 明确说出关键假设，达到什么条件才能验证 |
| 未知的未知 | 可能改变一切但目前不可见 | 场景分析，不是单点预测 |
| 数据冲突 | 不同来源给出矛盾数据 | 显式标注冲突，说明用哪个及理由 |

## 投资判断层

### 四个必答问题

1. **值不值得投**：技术可信度 × 商业化路径清晰度 × 团队执行力
2. **现在还是以后**：当前节点是否最优入场时机
3. **投什么**：具体哪家公司/哪个价位
4. **什么情况下改变判断**：哪些具体事件发生会让你重新评估

> 没有回答这四个问题的"投资分析"是市场研究，不是投资备忘录。

### 估值判断规范

必须包含：
- 当前估值是什么（具体数字，标注来源和时效）
- 你认为合理估值是什么（基于什么推算）
- 两者的差距及原因
- 在什么条件下当前估值会变得合理

❌ "估值偏高"不是结论

✅ "基于当前1000万收入，70亿估值≈700x P/S（市销率），需要收入在3年内增长10倍以上才能消化，而行业竞争格局支持这一路径的概率低于50%，因此建议等待回调至40–50亿"才是结论。

倍数必须写清口径：对收入用 P/S（市销率），对利润用 P/E（市盈率）。早期项目大多没有利润，不用 P/E；没有收入时，改用可比交易或"按人头 / 按里程碑"的估值逻辑，并说明假设。

### 关键 inflection 事件（强制要求）

每份赛道分析必须明确列出 2-3 个可观测的关键事件：

| 事件 | 预期时间 | 正面信号 | 负面信号 | 对判断的影响 |
|------|---------|---------|---------|------------|
| [事件1] | [时间] | [正面信号] | [负面信号] | [影响] |

> 没有这个表，分析就没有验证机制，无法被证伪，也无法迭代。

### 竞争动态分析（不可省略）

对每个主要竞争轴，回答：
- 如果A取得决定性优势，B会怎样？
- A和B争同一个客户时，客户选择依据是什么？
- 当前格局中，谁在打时间差，谁在打技术差，谁在打资源差？
- 什么样的技术突破或市场变化会重写当前格局？

## 语言规范

| 情境 | 应该写 | 不应该写 |
|------|-------|---------|
| 规模描述 | "2000万小时驾驶数据" | "大量驾驶数据" |
| 时间预判 | "2027年量产落地" | "不久后将落地" |
| 估值判断 | "等回调至40–50亿" | "估值较高时谨慎介入" |
| 不确定性 | "迁移曲线斜率未验证，当前无系统性证据" | "仍面临挑战" |
| 进度描述 | "处于Demo阶段，无付费客户，预计6个月内完成POC" | "仍处早期" |

## 写完后自查清单

```
□ 摘要里的每个结论，在正文都有具体证据支撑（而非再次声明）
□ 每个"是"都有对应的"不是"——边界清晰
□ 每个论点都有至少一条可被证伪的预测
□ 所有估值判断都有具体数字和推算逻辑
□ 玩家之间的竞争动态被明确分析（不只是并列画像）
□ 关键inflection事件被列出，并说明如何解读
□ 数据来源和时效都已标注
□ 不确定性被量化或条件化，而非用模糊语言掩盖
□ 结论对读者的决策有直接指导（投/不投/等待什么信号）
```

## 报告结构模板

### 赛道 Mapping 报告

```
1. 核心判断（300字以内，投资结论先行）
2. 赛道定义与边界（精确定义 + Why Now + 定义分歧说明）
3. 竞争格局Map（坐标轴 + 玩家定位 + 格局形成原因）
4. 关键变量分析（2-3个核心因素：现状→变化方向→触发条件→对格局影响）
5. 玩家深析（按格局位置分组：押注内容/当前进展/如果赢了/如果输了）
6. 投资判断（Buy/Watch/Pass + 估值分析 + inflection事件表 + 入场/失效条件）
7. 数据来源与不确定性说明
```

### 单项目深度分析

```
1. 结论（投资建议 + 估值判断 + 最关键的2个问题）
2. 项目定位（在赛道Map中的坐标 + 独特性）
3. 商业逻辑验证（客户是谁/为什么付钱 + Unit Economics + 现有证据）
4. 壁垒分析（当前壁垒来源 + 复制难度 + 壁垒随时间变化方向）
5. 团队评估（需要什么样的团队 + 当前团队匹配度 + 缺口）
6. 风险清单（技术/竞争/执行/时机四类风险）
7. 投资条款建议（估值/里程碑/保护条款 + 关键尽调问题≤5个）
```

## 格局未定赛道的特殊处理

对技术路线未收敛、商业化时间窗口不明的赛道，补充四个原则：

**原则1**：分开分析"技术可能性"和"商业可行性"（论据来源不同，置信度不同）

**原则2**：场景分析代替单点预测
```
乐观场景（概率X%）：触发因素是...
基准场景（概率Y%）：时间窗口是...
悲观场景（概率Z%）：谁受损/受益...
```

**原则3**：押基础设施优先于押路线（无论哪条路线都需要的东西，确定性更高）

**原则4**：定义观察期（明确说：我们在等哪3件事发生，才能把"观察"变成"判断"）
