# 赛道研判 Brief：六节骨架与深度标准

> 用途：为一个行业产出一份"投资人级赛道研判"——站在项目之上做技术判断与商业战略框架。可以直接交给能读工作区的 agent 执行，也可作为人工撰写的骨架。
> 铁律：绝不编造精度。数字必须带来源与时点（公司口径 / 可核对 / 待DD）；口径打架处明写「待对齐」，不平滑。

---

## 一、交付物：6 节骨架（锁定）

每个行业一份 `_赛道研判-<行业>.md`。已有材料的行业，是对照本骨架查漏补缺、升级第 2 节深度，不是推倒重写。

1. **定义与概念辨析**：它是什么；切开容易混淆的相邻概念（用控制方程当边界）。
2. **核心技术路线与差距**：见下文「第 2 节深度标准」，这是硬门槛。
3. **发展进度 / Milestone**：赛道走到哪、下一个里程碑、催化时点（回答"是不是现在"）。
4. **主要玩家**：大厂 / 明星创业公司 / 学院派，各站在哪条路线上。
5. **竞争格局（拆分）**：把玩家按「价值链层 × 技术路线」摆成一张图，判断价值沉在哪一层、谁被上下游挤压、赢家通吃还是多强共存。这一节最出 alpha。
6. **逐项目分析**：把已见项目落进第 5 节的图，各跑一遍「一分钟五问」。

---

## 二、第 2 节深度标准（硬门槛，不许退回「列路线菜单」）

用「**控制方程 → 必然流水线 → 每阶段挂投资判断 → 反直觉瓶颈**」四步：

1. **写出该领域优化的控制方程**，用它划边界、卡「叙事溢价」。
   - 视频生成 = `P(X₁:T | Prompt)`（开环条件生成）；世界模型 = `P(sₜ₊₁ | sₜ, aₜ)`（动作条件下的状态转移）。没有可干预的 aₜ 和可回灌的状态，就不是世界模型；用世界模型的估值讲视频生成的故事，应当打折。
2. **推导「必然存在」的流水线阶段**：被算力、显存、物理规律逼出来的收敛，而不是路线菜单。
   - 以视频生成为例：① 3D 时空 VAE 把视频压缩进隐空间；② DiT + 流匹配在隐空间里走噪声轨迹；③ 若要实时，则需要一致性蒸馏（少步）+ 因果掩码 + KV Cache + 锚点帧防漂移；④ 若要事实级可控，则用 VLM 生成布局作为硬约束，经 Cross-Attention 注入。
3. **每个阶段挂一条投资判断**。
   - 压缩比（8×8×4 ≈ 1/256）是 Unit Economics 的第一块砖；DiT 自研还是套壳，决定技术优势会不会归零；实时场景的单位成本 ≈ 单路显存 × HBM 占用时间 × 云单价 / 并发数，决定商业模式会不会裂；VLM 硬约束 + 失败样本回流形成闭环，决定复利资产在哪、该按基模公司还是应用公司估值。
4. **点出反直觉的真瓶颈**：例如 HBM 带宽往往比峰值算力更早"饿死"推理。

每个技术点的体例：**先写「为什么必然存在」→ 再写「投资人要懂到什么程度（能问出哪个硬指标）」→ 再承接下一阶段。**

## 三、投资人透镜（融进各节，不单开一节）

- **两根脊椎**：① 价值捕获——上游模型、下游分发能不能挤压它；② 复利——脱离前沿模型之后，它攒下了什么越用越厚的资产。主要落在第 5、6 节。
- **一分钟五问**（逐项目使用）：
  1. 三层蛋糕（模型 / 基础设施 / 应用）站在哪一层，上下游会不会挤它？
  2. 卡点是科学问题还是工程问题？
  3. 基模升级时它是笑还是哭（顺风还是路障）？
  4. 脱离模型，有什么在复利？
  5. 赚的钱往哪里漏，堵住了没有？
- **三层蛋糕**：模型层（烧钱、少数通吃）/ 基础设施层（卖铲子）/ 应用层（离钱近，但容易被上下游挤压）。

---

## 四、执行纪律

1. **不读原始材料就不下结论**：项目材料多为 CR 与访谈纪要，常存为 docx；用 `tools/docx_to_text.py` 转成文本再读。
2. **口径三档标注**：公司口径 / 可核对 / 待DD；打架处写「待对齐」。绝不为顺滑编数字。
3. **第 5 节是重心**：别停在列玩家，要判断价值沉在哪一层、谁被上下游挤压、赢家通吃还是共存。
4. **第 6 节逐项目跑五问**，汇成一张速览表，每个项目一句话 verdict。
5. **先切清相邻赛道的边界**：如世界模型 ↔ 视频生成、Agent OS ↔ 端侧基础设施、AI 泛娱乐 ↔ AI 游戏 ↔ AI 硬件。
6. **执行顺序**：先做从零起步的赛道（边际价值最高），再升级旧材料，最后对已完成的赛道查漏补第 5 节。可以按赛道并行分派子任务。
