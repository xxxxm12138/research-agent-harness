# Input vs Formula 规则（通用）

> 适用于所有 agent 生成的 Excel / 数据表，不限于 Cap Table。示例数字均为虚构。

---

## 核心原则

> **能从其他单元格推导出来的数字，必须写公式。不能推导的（外部给定的原始数据），才允许 key-in。**

---

## 为什么必须这样做

1. **可审计**：审阅者点开单元格就能看到计算逻辑，不需要反推。
2. **可联动**：改一个假设（如投资额），全表自动更新。
3. **防错误**：公式错了能被发现，key-in 错了无从验证。
4. **行业标准**：投行、PE、VC 的财务模型都这么做。

---

## 分类速查表

### 允许 key-in 的（INPUT）

| 类别 | 典型例子 |
|---|---|
| 法律文件约定的固定数值 | 注册资本 ¥2,000,000、投资额 $2,000,000 |
| 外部给定的参数 | 汇率 7.10（示例）、折现率 12%、退出倍数 8x |
| 协议明确的比例 / 条件 | 初始持股 60% / 25% / 15%（仅在"初始"列） |
| 时间 / 日期 | 成立日期、投资日期 |
| 文本标签 | 股东名称、轮次名称、列标题 |

### 必须用公式的（FORMULA）

除上述 Input 外，一切皆公式：

| 类别 | 公式类型 | 示例 |
|---|---|---|
| 加总 / 小计 | SUM | `=SUM(D21:D23)` |
| 比例计算 | 除法 | `=H21/$H$33` |
| 累计 / 累加 | 加法引用 | `=D21+G21` |
| 单价推导 | 除法 | `=G15/D33` |
| 数量推导 | 除法 + 取整 | `=ROUND(F27/G$17,0)` |
| 币种换算 | 乘法 | `=G7*$S$6` |
| 跨 section 引用 | 等号引用 | `=G7`（避免同一个数写两遍） |
| 验证行 | 差值 / 比较 | `=H30-D30-G30`（应 = 0） |

---

## Excel 公式书写规范

### 引用类型选择

| 场景 | 引用方式 | 原因 |
|---|---|---|
| 分母（总计行） | `$H$33` 绝对引用 | 全列共用同一个分母 |
| 每股价格 | `G$17` 锁行 | 同轮所有投资人共用 |
| 汇率 | `$S$6` 绝对引用 | 全表唯一 |
| 同行其他列 | `D21` 相对引用 | 横向复制时自动偏移 |

### 命名惯例（如使用 Named Ranges）

| 名称 | 含义 |
|---|---|
| `fx_rate` | 汇率 |
| `pre_money_r1` | 第 1 轮投前估值 |
| `pps_r1` | 第 1 轮每股价格 |
| `total_shares_r0` | 初始总股数 |

### 结构规则

1. **同一个数字只在一个地方 key-in**，其他需要用的地方用 `=` 引用。
2. **加总行永远用 SUM**，不手动加（即使只有 2 行）。
3. **百分比永远用除法公式**，不手写「10.00%」。
4. **验证行放在底部**：关键等式的差值应 = 0。

表格布局（每轮一组列、Input 与 Formula 的位置）见 `skills/deal-modeling/references/format-template.md`。

## 验证方法

生成 Excel 后必须验证：

1. **公式覆盖率检查**：数值型单元格中，formula 占比应 > 80%（input 极少）。
2. **联动测试**：修改一个投资人金额，检查投后估值、比例、加总是否自动更新。
3. **加总验证**：总计行 vs 手动加各行，结果一致。
4. **百分比验证**：所有 % 列加总 = 100%（或 = 1）。
5. **交叉验证**：投资额 / 每股价格 = 新增股数（ROUND 误差 ≤ 1）。
