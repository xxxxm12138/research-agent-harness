# Postflight Checklist — 出数后必须验证

> Excel 生成完毕后（Step 3 完成），以下每项必须验证通过。任何一项失败 = 返工。

---

## 数据准确性

- [ ] **股东名称与协议逐字比对**（复制协议原文 vs Excel 内容，逐字核对）
- [ ] **初始注册资本总额与协议一致**（如协议写 ¥2,000,000，表里总计必须 = 2,000,000）
- [ ] **各投资人投资金额与协议一致**（逐笔核对）
- [ ] **投前估值与 Term Sheet 一致**
- [ ] **汇率数值正确**（核对央行网站或协议约定）

## 数学验证（公式交叉检验）

- [ ] **各轮持股比例加总 = 100%**
  - 总计行的 % 列 = 1.0000（或 100.00%）
  - 如果不等，说明公式有错
- [ ] **投前 + 本轮总投资 = 投后**
  - `投前估值单元格 + 本轮总额单元格 = 投后估值单元格`，三个数交叉验证
- [ ] **投资额 / 每股价格 = 新增注册资本**（允许 ROUND 误差 ≤ 1）
  - 对每个投资人逐一验证：`F27 / G$17` 应 ≈ `G27`（差异来自 ROUND）
- [ ] **新增注册资本总计 = 总股数增量**
  - `本轮后总计 - 上轮后总计 = 本轮新增小计`

## 公式完整性

- [ ] **公式覆盖率检查**：除 Input 外，所有数值单元格都是公式
  - 方法：选中数据区域 → Ctrl+` 切换公式视图 → 确认没有遗漏的硬编码
- [ ] **联动测试**：修改一个投资人金额，检查投后估值、新增注册资本、比例、加总行是否自动更新；测试完改回原值
- [ ] **引用正确性**：分母都用了绝对引用 `$`；每股价格都锁了行；汇率都用了绝对引用；无循环引用

## 格式验证

- [ ] **字体**：Times New Roman 11pt
- [ ] **表头**：灰色背景、居中
- [ ] **边框**：medium weight、全边框
- [ ] **数字格式**：金额千分位（#,##0）、百分比两位（0.00%）
- [ ] **对齐**：数字右对齐、文本左对齐
- [ ] **列宽**：无截断、无过宽

## 结构验证

- [ ] **Pro Rata 位置正确**：在新轮次 section 下独立成行（不是放在老轮次行的右边）
- [ ] **Section 分组正确**：原有股东 / 各轮投资人 / 总计
- [ ] **底部汇总表**（如需要）：合并同一投资人跨轮持股
- [ ] **格式与模板一致**（`skills/deal-modeling/references/format-template.md`）

## 商业常识

- [ ] **稀释比例合理**：种子轮 10-25% 常见；A 轮 15-25% 常见；超过 30% 需要特别说明原因
- [ ] **每股价格递增**：后轮 > 前轮（除非 down round）
- [ ] **投资人持股与投资额匹配**：投得多的占比应该更高

---

## 通过标准

**全部打勾** → 任务完成，可以交付
**任何一项失败** → 定位错误根因，修复后重新验证

## 常见失败原因

| 症状 | 通常根因 |
|---|---|
| 比例加总 ≠ 100% | 总计行公式遗漏了某个 section |
| 联动测试失败 | 某个单元格硬编码了，而不是公式 |
| 名称不匹配 | 从草稿复制，而不是从协议复制 |
| 注册资本总额不对 | 单位搞错（万元 vs 元） |
| Pro Rata 位置错 | 放在了上轮投资人行的右边 |
