# Call Report 写作规范

**用途**：CR 写作的操作规范，供 AI 工具（把会议录音自动转成 CR）和分析师（手动撰写）共同使用。
**文档结构**：本文件是规则总纲；`skills/call-report/reference/` 下是配套材料（模板、打分锚点、术语校验表）；`skills/call-report/cr-agent/AGENT.md` 是端到端执行的 agent 定义。

**适用场景**：把会议录音、逐字稿或笔记转化为可直接提交的 Call Report。
**核心原则**：CR 是信息快照，不是判断文档——不评判，只呈现，让数字自己说话。

> 本仓库的示例均为虚构。真实 CR、录音与逐字稿属于保密材料，不进入仓库。

---

## 核心写作准则（六条铁律）

1. **不评判，只呈现**：删除所有写报告者的主观判断（"正向信号""技术审美好"）。创始人的判断标注为"团队认为"。
2. **紧凑 > 完整**：宁可少一个模块，也不放水稀释信息密度。早期项目三章即可。
3. **数字自己说话**："7B 参数""50 万+条轨迹""成功率 41%"——不加形容词。
4. **口语可留**：有行业精准度的口语（"刷分""兜底""这事很难"）比硬翻成书面语更好。
5. **一句一事**：每个 bullet 只承载一个独立信息点。
6. **FA 操作不入 CR**：内部推进细节（谁否决了、FA 反馈、覆盖了多少家机构）不写入正文。

## 执行流程

### Step 1：确认输入材料

用户提供以下之一：会议录音转文字、会议笔记 / 逐字稿、其他原始材料。CR 的目标是固定的：呈现公司信息快照，供决策者判断。

### Step 2：信息提取与分类

| 类型 | 保留 | 删除 |
|---|---|---|
| 事实 | 团队背景、技术路线、产品进度、融资数据 | — |
| 创始人判断 | 标注为"团队认为…""创始人判断…" | 不标注来源的观点 |
| 无效信息 | — | 寒暄、重复、离题比喻、FA 操作细节、纯销售话术 |

### Step 3：按模板结构组织

按 `skills/call-report/reference/call-report-template.md` 组织。关键决策：

- **早期项目（种子 / 天使）**：可只保留三章（公司业务 / 行业情况 / 融资需求），删除竞争优势和风险因素独立章节。
- **中后期项目（A 轮+）**：使用完整五章结构。
- **表头和打分表**：无论阶段，必须完整填写。

### Step 4：语言处理

**去什么：**

| 删除类型 | 示例 |
|---|---|
| 纯闲聊比喻 | "这就跟我们小时候搭积木一样" |
| 写报告者主观判断 | "是研究诚实性的正向信号" |
| 冗余展开 | 同一个意思说两遍的段落 |
| 无锚定的模糊信息 | "进展顺利""表现良好" |
| FA / 内部操作细节 | "上周已经给几家机构过了一遍""领导还没看" |
| 教育读者的内容 | "这是整个赛道的客观局限，不仅是这家公司的问题" |

**留什么：**

| 保留类型 | 示例 |
|---|---|
| 有行业精准度的口语 | "这事很难""无法被刷分""兜底硬件缺陷" |
| 创始人核心判断（标来源） | "团队认为数据闭环比模型规模更关键" |
| 所有数字 | "0.8 元/分钟""月均 20 万""投后 3000 万美元" |
| 具体时间节点 | "3/15 成立""达到 10 万小时数据目标需要 9 个月" |

**术语规范：**

| 场景 | 正确用法 | 说明 |
|---|---|---|
| 公司架构 | "JV 架构""VIE 架构""开曼架构" | 按实际架构精确使用，不可混淆 |
| 金额简写 | "3kw 人民币""~1 亿美元" | 行内简写可用 |
| 技术术语 | "VLA""Latent space""预训练" | 保持英文 / 标准写法 |
| 学历简写 | "XX 大学 PhD""XX 大学本科" | 表头可简写 |
| 融资术语 | "投后""TS""SAFE""FA" | 保持行业标准缩写 |
| 顶会名称 | "CVPR""AAAI""NeurIPS" | 不加中文翻译 |

### Step 5：填写打分表

- 每个维度 1–5 分（可用 0.5 分），参考 `skills/call-report/reference/scoring-anchors.md`。
- 无法评价的填 NA。
- **打分表即判断层**：正文不做判断，判断通过分数体现；不需要逐项写评分依据。
- ⚠️ **由项目负责人填写**。AI 从录音生成 CR 时，打分表留空待人工补填。

### Step 6：术语校验（输出前必做）

按 `skills/call-report/reference/terminology-checklist.md` 执行三步校验：

1. 法律架构词：VIE / JV / 红筹是否与公司实际架构一致？
2. 技术术语拼写：Latent 不是 Late，Diffusion 不是 Diffussion。
3. 金额单位：每个数字有币种，并标注投前 / 投后。

**术语错误是致命伤，一个都不能有。**

### Step 7：输出格式

纯文本（Tab 分隔表格 + 层级 bullet），可直接粘贴进 Word。

## AI 可做 vs 人必须补

| 内容 | AI 从录音提取 | 人工补填 |
|---|:---:|:---:|
| 正文（公司业务 / 行业 / 融资） | ✅ | — |
| 表头：企业名称 / 业务简述 / 参会人 / 行业 | ✅ | — |
| 表头：项目负责人 / 项目来源 / 竞争 FA | — | ✅ |
| 表头：客户分级 / 潜在交易规模 | — | ✅ |
| 打分表 | — | ✅ |

**规则**：AI 输出的 CR 中，人工补填字段标注 `[待填]`，不留空，也不猜。

## 信息颗粒度标准（示例均为虚构）

| 信息类别 | 颗粒度 | 示例 |
|---|---|---|
| 创始人履历 | 学历 + 关键工作经验 + 代表成果 | "海外高校博士在读，入学前 3 年工业界视觉算法经验；代表工作为一个 7B 参数的视频预测模型和一个 15 FPS 的实时控制方法" |
| 团队规模 | 总人数 + 地域分布 | "~10 人，国内 6 人、海外 4 人" |
| 技术路线 | 核心选择 + 差异点（2–3 条） | 不做论文摘要式展开 |
| 数据策略 | 目标 + 来源配比 + 当前量 + 成本 | 每项一句 |
| 产品进展 | 成立时间 + 当前阶段 + 检验方式 | "公司 3/15 成立；Demo 阶段，以桌面整理任务为检验" |
| 融资 | 历史轮次 + 本轮金额估值 + 下一轮目标，1–2 句 | "种子轮两家人民币基金合计 ~3kw 人民币，投后 ~3000 万美元；本轮美元基金交割中，投后 ~8000 万美元" |
| 行业信息 | 只保留影响该公司的关键变量 | 不做赛道百科 |

## 结构精简原则

| 公司阶段 | 必须有的章节 | 可省略 |
|---|---|---|
| 种子 / 天使 | 公司业务 + 行业情况（关键变量）+ 融资需求 | 竞争优势独立章节、风险因素独立章节、竞争对手详细展开 |
| Pre-A / A 轮 | 全部五章 | — |
| B 轮+ | 全部五章 + 运营 / 财务数字 | — |

**无论阶段，表头信息卡和打分表必须 100% 填写。**

## 常见失误

| 失误 | 修正 |
|---|---|
| 写报告者的主观判断混入正文 | 删除。判断由打分表承载 |
| 口语全部硬翻成书面语 | 有信息量的口语保留原味 |
| 竞争对手展开成名片夹 | 早期项目可不单列竞争对手 |
| 风险因素大段展开 | 早期项目可省略独立风险章节 |
| 融资部分含 FA 内部操作信息 | 只写对外事实（轮次 / 金额 / 架构） |
| 信息过度展开（每个 bullet 3 句以上） | 一句一事，超过就拆 bullet |
| 打分表留空 | 必填；不确定的写 NA |
| 术语不一致 | 同一概念全篇用同一术语 |
| 正文出现「会议称」等元表述 | 直接陈述事实（见 `agent/memory/corrections.md`） |
